# 页面契约与补采判断

仅在多页、复杂动态状态、异步/滚动容器或跨轮交接时读取。简单任务无需逐项填表，也无需创建单独契约文件。

## 最小取证六要素与记录格式

围绕当前最小业务闭环，只记录会影响实现、验收或恢复的事实：

| 维度 | 记录要点 | 示例（列表 / 详情 / 弹窗 / 提交后） |
| --- | --- | --- |
| 1. 入口与身份 | 进入路径；如何确认站点、账号/商家、页面与目标记录一致 | URL 路径、租户标记、表头、与列表一致的记录 ID |
| 2. 作用域 | 所属 page、iframe、弹窗、行或 Shadow Root 及动态标识 | 弹窗容器、所属 frame 路径、目标行 |
| 3. 定位依据 | 稳定语义/属性、候选数量、业务关联、可见与可操作条件 | 可复现定位方法，排除全局首个同名节点 |
| 4. 数据语义 | 字段真实含义、来源、格式、单位、合法空值与解析错误区分 | 可选字段真实不存在记合法空，不与缺失混淆 |
| 5. 动作与状态 | 关键动作前后变化；加载中、成功、明确空结果、登录失效、异常 | 列表行加载结束或明确空信号；显示值与目标一致 |
| 6. 结果回读 | 证明动作生效的页面事实或远端结果；是否存在二次确认 | 远端状态/回执/列表刷新；点击成功或 toast 不等于生效 |

证据应能回答“哪个状态下、哪个范围内、哪个目标”，可引用脱敏结构快照、截图、必要响应片段或运行日志，不要求同时具备全部形式。

## 容易造成假闭合的情况

- **iframe**：导航后的 frame 位置不能证明点击前菜单所在位置；动态 frame 名不宜写死，按稳定 URL 路径和内容身份解析。
- **弹窗**：截图看见“确认”只证明它存在，不证明 DOM、可操作节点、选中态和副作用；真实操作前须补足这些信息。
- **Shadow DOM**：普通 HTML 快照可能不含目标字段；确认是否为 open shadow root 及工具是否支持穿透，closed root 无法访问时如实报告能力缺口。
- **虚拟列表与动态滚动**：DOM 行数不是总条数；除核对业务键与真实结束信号（如容器 `currentPage`/`lastPage`）外，还需核对**触发加载的真实条件**——哨兵属性可能在翻页后不更新，触底像素阈值（如 `< 1px`）也可能受视口高度或系统缩放（DPR）取整影响而无法命中。区分加载未触发、已触发但未推进、已到终点。前两种状态保留已有结果，并在覆盖仍不明确时标记未确认。
- **异步页面**：主文档已加载但列表仍转圈或脚本未绑定事件，属于未就绪；零条数据只有在明确空结果信号或可核对响应下才可靠。
- **多候选**：不靠第一个、最显眼或行数最多猜测；补充作用域或业务关联，直到足以排除误操作。
- **网络响应**：确认它对应本次筛选/目标，检查业务错误而非只看 HTTP 200；字段完整性与详情关联另外核对。
- **文件上传**：选文件可能触发自动上传；按该站点实际行为区分“选择、上传、确认生效”，不能预设每一步无写入。

## 动态重建与离线占位

- **SPA / 弹窗 / frame 重建**：导航或切换后按需重新解析目标，旧节点引用失效不直接等同业务失败；临时快照引用不直接固化为持久选择器。
- **网页暂不可用时**：可先开发离线解析、状态机与存储逻辑，但真实选择器必须标为待确认，避免把猜测固化为实现。
- **局部缺口阻塞**：缺少会影响真实操作的节点或回读依据时，只把对应部分标为待取证/阻塞，其余独立部分可继续。

## 是否需要补采的三个问题

1. 当前证据缺少什么，会让哪段代码依赖猜测？
2. 最少观察哪个页面状态、节点或站点脚本能消除这个未知？
3. 观察是否会产生未授权副作用？若会，能否用现有证据、测试环境或脱敏材料替代？

答案明确后只补对应缺口；已有证据的身份、页面版本和路径仍适用时直接复用，不重采全流程。
