# 页面契约与补采判断

仅在多页、复杂动态状态或交接时使用。简单任务无需逐项填表，也无需创建单独契约文件。

## 可选的最小记录格式

| 状态/步骤 | 目标身份与作用域 | 控件或字段的证据 | 就绪/结果信号 | 缺口与影响 |
| --- | --- | --- | --- | --- |
| 列表 | URL 路径、商家标记、表头、frame 路径 | 目标行与业务 ID 的关联 | 行已加载或明确无结果 | 未观察下一页，不宣称全量 |
| 详情 | 与列表相同的记录 ID、详情容器 | 字段标签与值的对应 | 必需正文出现且加载结束 | 可选字段真实不存在可记录合法空 |
| 编辑弹窗 | 弹窗容器、所属 frame、当前记录 | 输入、选项、选中状态、保存、关闭 | 显示值与目标一致 | 未观察保存后结果则真实保存未验收 |
| 提交后 | 原记录/任务 ID、结果页面 | 状态、回执或远端列表 | 能证明业务已成功的事实 | 点击成功或 toast 不一定证明最终生效 |

证据应能回答“哪个状态下、哪个范围内、哪个目标”。可以引用现有脱敏结构快照、截图、必要响应片段或运行日志；不要求同时具备全部形式。

## 容易造成假闭合的情况

- **iframe**：导航后的 frame 位置不能证明点击前菜单所在位置；动态 frame 名不宜写死，按稳定 URL 路径和内容身份解析。
- **弹窗**：截图看见“确认”只证明它存在，不证明 DOM、可操作节点、选中态和副作用；对真实操作需要补足这些信息。
- **Shadow DOM**：普通 HTML 快照可能不含目标字段；检查是否为 open shadow root、工具是否支持穿透；closed root 无法访问时如实报告能力缺口。
- **滚动加载与虚拟列表**：用业务键确认新增记录，避免把当前 DOM 行数当成总量。列表停滞时，按需核对滚动位置、哨兵、请求或加载状态，区分加载未触发、已触发但未推进、已到终点。前两种状态保留已有结果，并在覆盖仍不明确时标记未确认。
- **异步页面**：主文档已加载但列表仍转圈，属于未就绪；零条数据只有在明确空结果信号或可核对响应下才可靠。
- **多候选**：不靠第一个/最显眼/最多行猜测。补充作用域或业务关联，直到足以排除误操作。
- **网络响应**：确认它对应本次筛选/目标，检查业务错误而非只看 HTTP 200；字段完整性与详情关联另外核对。
- **文件上传**：选文件可能触发自动上传；“选择、上传、确认生效”按该站点实际行为区分，不能预设每一步无写入。

## 是否需要补采的三个问题

1. 当前证据缺少什么，会让哪段代码依赖猜测？
2. 最少观察哪个页面状态或节点能消除这个未知？
3. 观察是否会产生未授权副作用？若会，能否用现有证据、测试环境或用户提供的脱敏材料替代？

答案明确后只补对应缺口。每个阶段无需重采全流程；已有证据的身份、页面版本和路径仍适用即可复用。
