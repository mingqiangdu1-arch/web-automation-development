# 路线探索与交接

首次接入、混合操作或计划替换执行路径时按需阅读。低风险小修复沿用已验证路径即可。工具 API、参数与版本以当前安装环境及官方文档为准，不固定依赖版本，不要求安装新工具。

## 常见场景与选型参考

| 场景 | 选型与避坑要点 |
| --- | --- |
| 公开静态页或批量公开内容 | 可用 HTTP/解析器或现有抓取工具；先确认返回的是正文而非挑战页或空壳 |
| 登录后交互、iframe、弹窗、动态数据 | 复用项目已有 Playwright、DrissionPage 或浏览器工具；先读对应工具文档 |
| 临时页面探索 | 先看目标区域或交互元素，动作改变状态或引用失效后再刷新；结构证据不足时再补截图、日志或 trace |
| 持续复用的操作 | 用已验证契约封装适配器；临时快照引用不直接成为持久选择器 |
| 页面正常加载响应中的结构化数据 | 可在获授权访问内监听响应并与页面记录 ID 对齐；监听必须早于触发动作 |
| 长时轮询或批量任务 | 再考虑检查点、Profile 单实例锁及浏览器生命周期管理 |

## 路线切换原则

- 已验证路线满足业务正确性、运行规模和维护要求时，默认继续复用。
- 仅在出现可测量性能瓶颈、已观察到的可靠性问题、维护成本过高、业务能力缺失，或发现更合适的正式接口时，才评估替换（UI → API 与 API → UI 同标准）。
- 切换前验证新旧路线在业务对象及租户、字段语义、权限、副作用、完成判据和错误恢复上等价；存在业务差异时明确影响，不作等价替换。
- 写入结果不明时严格遵循 `SKILL.md` 的写入恢复规则：先查远端状态，不得自动切换执行器补写。

## 探索与交接

- **先拆业务，再选工具**：针对影响实现的步骤，明确业务对象、前置状态、读写性质与完成信号（提交受理和最终生效可能是两步）。正式 API 核对权限、业务字段、分页、限流与批量能力；DOM/视觉核对定位、页面状态与结果回读。
- **区分三类接口证据**：官方文档说明受支持契约；获准页面操作中观察到的响应只证明该样本行为；主动调用未公开接口须另有明确许可，并核对业务语义、维护成本与运行条件。不绕过访问控制、验证码或站点限制，不留存会话凭据；不能证明可用时保留为候选或沿用已证实页面路径。
- **最小样本交叉验证**：比较同一记录、过滤条件、字段口径和远端状态；写入验证仅限获准范围，未测写入交接为待验证。涉及性能选型时先量现有瓶颈再比替代路线。
- **混合路线与补充核验**：仅在确有收益时混用执行方式，且共享业务对象标识、完成判据与恢复规则。先选能完整交付主结果的路线；补充核验失败时不要悄悄丢弃主路线有效记录，任务要求逐条核验而无法满足时如实报告缺口。

交接用几行或一张表即可：**操作｜拟选路线及理由｜证据状态与来源｜完成判据｜缺口及影响**。区分已观察、已推断、已验证（注明样本和范围）、未验证、已阻塞。关键步骤已有足够实现证据，或缺口与下一步明确时，即停止探索。

## 沉淀可复用能力

- **站点级契约**：入口、认证方式、公共页面结构与接口约束，按需读取。
- **任务级契约**：具体流程、步骤路线、业务成功信号与验证样本。
- **已验证能力**：多处实际复用时封装独立操作（列表查询、详情读取、增量分页、填表、结果回读），标明输入输出、前置状态、权限副作用、完成信号、失败状态与验证范围；查询与提交按权限分别表达。

优先复用已有适配器、API 客户端或混合模块；页面、权限、字段或接口变化时只重验受影响操作。无需为每项能力创建新 Skill、注册中心或独立文档。
